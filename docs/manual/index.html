Glossary

TkVillage

TkVillage is a small runtime for building modular, multi-window Tkinter applications. It creates the hidden Tk root, manages visible Toplevel windows, runs a periodic tick loop, and gives each window a predictable event, reducer, effect, and projection flow.

TkVillage In One Minute

TkVillage helps keep Tkinter programs from turning into scattered widget callbacks and shared-variable mutation. You declare the app, register reusable window kinds, summon live windows, post semantic events from widgets, update state through reducers, and let projections update the interface from that state.

  1. Declare the app with declare_app({...}).
  2. Register window kinds with creation, reducer, and projection functions.
  3. Summon windows. TkVillage creates, raises, or tracks them according to policy.
  4. Post semantic events from widget callbacks.
  5. Let reducers update window state and request effects.
  6. Let projections copy state into visible widgets.
  7. Let the tick loop coordinate queued work and shutdown checks.

TkVillage Owns

Runtime responsibility What that means
Hidden Tk root TkVillage creates and manages the process-level Tk root.
Window registry Window kinds and live windows are tracked in runtime dictionaries.
Queues and tick loop Events, messages, effects, projections, and shutdown checks run through periodic ticks.
Lifecycle coordination Window close behavior and app shutdown follow the declared policy.

User code What it does

Create functions Build the widgets for a live Toplevel window.
Reducers and projections Reducers update state; projections update widgets from state.

Core Vocabulary

Term Plain meaning
Window kind A reusable definition for a type of window.
Window A live Toplevel instance created from a window kind.
Event A semantic dictionary saying that something happened.
Reducer A function that updates state in response to an event.
Projection A function that updates existing widgets from current state.
Target A routable recipient, usually a window or service.
Tick One runtime pass through queued events, effects, projection, and shutdown checks.

The Runtime Shape

A user action runs a Tkinter widget callback.
The callback posts a semantic event, such as {"type": "increment"}.
The next tick drains queued work and sends the event to the target window or service.
A reducer updates state and may request explicit effects.
Dirty windows are projected, effects are routed, and shutdown is checked.
lionscliapp is optional. TkVillage can run standalone. When a program already uses lionscliapp, TkVillage can use its project-folder timing and keep TkVillage-specific files under that project folder.
